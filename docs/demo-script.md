# 6 分 30 秒演示脚本

录制规格：1920×1080 或更高，MP4，普通话讲解。使用实际运行画面；不要把预设画面冒充 AI 实时输出。录制前关闭其他含隐私的窗口，保证 Docker 启动、模型余额可用。不要展示 .env。

## 0:00–0:40 问题与定位

“初学者常常能看懂答案，却不知道自己的程序为什么错。知错把真实实验结果作为诊断证据，让 AI 给出下一步练习，再用复测确认改进。”展示总览。说明作品独立实现，服务运行在本机。

## 0:40–1:30 基础验证与知识图谱

选择 Python，独立回答六道阅读题。展示雷达和先修关系。解释每维目前仅一道题，只作入门筛查，不代表天赋或全面能力评定。

## 1:30–2:30 真实失败

统计正数实验输入以下故意含错代码，并明确说“这是演示用的错误实现”：

```python
def solve(numbers):
    return sum(1 for n in numbers if n >= 0)
```

运行全部测试。指出 [-1,0,2] 的预期为 1，实际为 2。展示零值边界排查建议。解释这些结果来自 Docker 内实际运行，不是模型猜测。

## 2:30–3:50 AI 工具调用与资料依据

在资料库导入自己编写的课程笔记：“正数是严格大于零的数，0 既不是正数也不是负数。统计正数时使用 > 0；测试包含空数组、零、负数和正数。”

进入 AI 诊断工作台，请求：“根据我的实验失败记录，解释可能原因，检索相关资料，安排下一步练习。”生成过程中解释只读工具边界。展示实际调用轨迹和来源片段；若未检索到资料，照实说明，不预设成功引用。

## 3:50–5:00 修正与复测

把 >= 改成 >，运行原实验，确认全部通过。到补弱页进入对应复测，自己写入同样语义的函数，不调用提示，再运行。展示状态变化。说明复测是不同输入组，只说明本组测试通过，不能认证是否独立思考。

## 5:00–5:40 工程能力

打开运行环境，展示七种语言状态。选择 JavaScript 或 Java 执行一题。展示资料管理和数据导出，不在录屏中打开含个人数据的导出文件。

## 5:40–6:30 架构与总结

“React/TypeScript 负责交互，Node.js 控制证据和模型调用，Docker 隔离学生代码。AI 无权改成绩或执行系统命令。课程检索采用关键词分段检索，工具调用采用 Function Calling。当前没有多模态、MCP 或向量数据库，不做这些能力的虚假宣传。”

最后展示测试结果、真实局限与未来方向：扩展题库、独立班级试点、更丰富的检索评价。
